# Contributing


Thank you for improving this project. Before opening a pull request, discuss material new features or large changes in an issue so the implementation fits the project's direction.

## Development

Follow this repository README for setup and checks. Use public exports, linked source, pinned packages or supported hybrid selections. Follow the owning language, strict types, formatting and lint rules; keep changes focused with meaningful tests. Do not add generated build output, credentials, API keys, vendor copies or unrelated formatting changes.

## Rights and licensing

By submitting a contribution, you confirm that you have the right to submit it under the repository's applicable licensing terms and that it does not include confidential, proprietary, or copied material without permission. Identify all third-party code, data, models, textures, sounds, fonts, and references in the pull request.

Creative assets need explicit provenance records and the owning repository asset-license guidance. Do not submit a model or reference merely because it is publicly downloadable.

## Pull requests

Explain the user-visible result, relevant tests, and any limitations. Update documentation when public behavior, setup, data sources, or licensing changes. Maintainers may request a smaller change, more tests, or provenance evidence before merge.

## Weather ownership and validation

Use the current manual wind contract and explicit host state boundary. Preserve
source attribution, original licenses/notices and declared units. New weather
capabilities need their staged specification and acceptance evidence; do not
infer qualified atmosphere/cloud/turbulence behavior from the two controls.

Check changed source in its owner and reserve the shared coordinator window
before execution. Keep caches local and incremental and retain dated build logs.
The shared pinned foss-earth/ci caller and conformance suite must inspect metadata
for every change, including docs-only contributions. Their final pins and actual
remote admission settings remain pending; no private replacement checker is used.

## Commit attribution

You cannot have AI as a co-author, or your contributions will be rejected.

Do not add AI author, committer or co-author attribution. Branded AI contributor
credits put a vendor name in permanent contribution records and can imply
endorsement. This project treats that promotion as advertising and bans it in
contribution credits to keep contributor recognition independent of vendor
promotion and responsibility clear. The human submitting work remains
accountable for accuracy, review responses, provenance and rights. Required
license notices, factual tool documentation and legitimate human credits remain
valid.
